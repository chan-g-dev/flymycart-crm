# Application review — 28 September 2026

Reviewed the local working tree from Dashboard through Settings, preserving the earlier performance and invoice-logo changes. Confirmed bugs were fixed. No production data was changed, and nothing was committed, pushed, or deployed.

## Fixes from this review

- **Reports:** the selected operating center now reaches the API. Collections, collection breakdowns, expenses, and carrier payments follow the report's center/scope/entity filters. These filters still intersect staff access restrictions.
- **Reports:** refunds approved during the reporting period are included even when the shipment was booked in an earlier period. Invalid dates, months, and scopes are rejected. Database/serialization failures are no longer silently converted into zero totals or omitted shipment rows.
- **Reports:** removed filter counts derived from whichever shipments happened to have loaded during earlier navigation. Period totals remain in the report itself. Added a retry action for failed report requests.
- **Settings:** legacy courier, center, employee, entity, wallet, and payment-provider editors now await successful saves, retain input on failure, show errors, and prevent overlapping saves. Removed optimistic cache writes before server confirmation.
- **Settings activity log:** loads when opened, refreshes when reopened, and distinguishes loading/failure from an empty log, with retry support.
- **Users:** failed suspension/reactivation no longer changes the displayed status or claims success. Staff-directory refresh errors are visible and clear after recovery.
- **Global search:** shipment prices and invoice total/paid/balance fields now respect customer-price access. Hidden amounts are not displayed as zero in the search UI.
- **Follow-ups:** cancelled reminders no longer appear in the due/overdue work queues.
- **Exports:** replaced the duplicate staff CSV implementation with the shared quote-escaping and formula-safe exporter. Account exports await the deferred spreadsheet library before clearing their busy state.
- **Cleanup:** removed unused imports, obsolete report-count calculations, duplicate CSV generation, and error-swallowing report fallbacks. The frontend import graph found no unreferenced application source files; no feature files were deleted speculatively.

- Live hosting, production PostgreSQL execution plans/load, remote storage delivery, and a deployed-version walkthrough were not revalidated in this pass. Local test results do not establish live production readiness.
- Credit Payment Alerts remains explicitly marked **In Dev**. Automated external reminder delivery is not certified, and no external messages were sent.

- Earlier performance gains and invoice customization remain local until the frontend and backend are deployed together.
